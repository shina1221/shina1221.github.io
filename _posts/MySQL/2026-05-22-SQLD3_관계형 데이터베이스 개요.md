# 정리  
SQL 종류  
데이터 조작어(DML//Manipulation): select, insert, update, delete  
데이터 정의어(DDL//Definition):create, alter, drop, rename  
데이터 제어어(DCL//Control):grant, revoke  
트랜잭션 제어어(TCL): commit, rollback  
</br>  
ERD:테이블 간 서로의 상관관계를 그림으로 도식화한 것을 E-R 다이어그램이라고 함  
엔티티, 관계, 속성 세가지로 구성됨  
</br>  
CHAR:고정길이 문자열로 변수값이 기준보다 작다면 공백으로 채워짐  
VARCHAR:가변길이  
NUMBER:정수와 실수저장  
</br>  
제약조건: 원하는 조건의 데이터만 유지하기 위해 생성하는 것으로 데이터의 무결성을 유지하기 위해 특정 컬럼에 설정하는 제약  
*데이터 무결성: 데이터가 생성, 전송, 저장되는 전 과정에서 변경되거나 손상되지 않고 정확성, 일관성, 유효성을 유지하는 것  
ex)기본키, 고유키(unique key), not null, check, 외래키  
고유키(unique key)로는 기본키와 다르게 null 입력가능  
unique 인덱스가 생성되는 것은 기본키  
check:입력할 수 있는 값 종류 및 범위 제한
</br>

트랜잭션의 특성(ACID)  
원자성:트랜잭션에서 정의된 연산들은 모두 성공적으로 끝나거나 모두 실패  
**일관성**:트랜잭션이 실행되기 전의 데이터베이스의 내용이 잘못되어 있지 않다면 실행된 이후에서 데이터베이스의 내용에 잘못이 있으면 안됨  
고립성:트랜잭션이 실행되는 도중에 다른 트랜잭션의 영향 을 받아 잘못된 결과를 만들어서는 안됨  
**지속성**:트랜잭션이 성공적으로 수행되면 그 트랜잭션이 갱신한 데이터베이스의 내용은 영구적으로 저장됨  
일관성 = 데이터 규칙이 깨지지 않는 상태 유지  
지속성 = “커밋된 데이터는 영구 저장  
</br>  
자동으로 커밋되는 때
CREATE, ALTER, DROP, RENAME, TRUNCATE TABLE 등 DDL 문장을 실행하면 그 전후 시점에 자동으로 커밋됨  
DML문장 이후 커밋 없이 DDL 문장이 실행되면 DDL 수행전 자동 커밋  
어플리케이션 종료로 db와 접속이 단절되면 트랜잭션 자동 롤백  
</br>  
집계함수의 통계 정보는 NULL값을 가진 행 제외 후 수행  
HAVING 절은 GROUP BY 절의 기준 항목이나 소그룹의 집계 함수를 이용한 조건을 표시  
SELECT 절에 기재하지 않은 컬럼을 기준으로 ORDER BY 해도 정상적으로 실행  

# 헷갈리는 부분 정리  
데이터베이스(DB)와 데이터베이스 관리 시스템(DBMS)의 차이  
**DB는 DBMS에 의해 통제됨**  
DB는 데이터 자체를 안전하게 저장하고 보존할 목적으로만들어진 구조회된 데이터 창고  
DBMS는 데이터 검색, 수정, 보안, 백업, 동시접근 제어를 목적으로 만들어진 데이터를 관리/운영하는 SW  
**DB는 테이블, 인텍스, 뷰 등**  
DBMS는 Oracle, MySQL, MongoDB  
</br>  
필드:컬럼과 행이 겹치는 하나의 공간  
NULL: 아직 정의되지 않은 미지의 값이거나 현재 데이터를 입력하지 못하는 경우
</br>  
renane column은 oracle 등 일부 dbms에서만 지원  
**tuncate 수행시 rollback 불가능**  
커밋(Commit): 트랜잭션(작업의 논리적 단위)이 성공적으로 완료되었음을 시스템에 알리고, 데이터 변경 사항을 데이터베이스에 영구적으로 반영하는 명령어  
커밋 후 이전 데이터는 영원히 잃어버리게 되고 모든 사용자는 결과를 볼 수 있음, 관련된 행에 대한 잠금(locking)이 풀리면서 다른 사용자들이 행조작 가능  
커밋 이전에는 메모리 buffer에만 영향을 받아 이전 상태로 복구 가능  
*DB 락(Lock):여러 트랜잭션이 동시에 같은 데이터에 접근할 때 충돌을 방지하고, 데이터의 무결성과 일관성을 유지하기 위한 상호 배제(Mutual Exclusion) 동시성 제어 메커니즘  
롤백 시 이전 상태로 복구되며 관련 행에대한 잠금이 풀려 다른 사용자들이 데이터 변경 가능  
복잡한 대규모 트랜잭션에서 에러가 발생했을 때 SAVEPOINT까지의 트랜잭션만 롤백하고 실패한 부분에 대해서만 다시 실행  
<>는 not을 의미  
sign함수는 양수면1, 음수면-1, 0이면 0반환  
mod는 나머지 반환

**GroupBY와 Having은 서로 위치를 바꿀 수 있음**  
```
SELECT
A.EMP_NO
, (SELECT L.EMP_NM FROM TB_EMP L WHERE L.EMP_NO = A.EMP_NO) AS EMP_NM
, MAX(A.PAY_AMT) AS MAX_PAY_AMT
, MIN(A.PAY_AMT) AS MIN_PAY_AMT
, ROUND(AVG(A.PAY_AMT), 2) AS AVG_PAY_AMT
FROM TB_SAL_HIS A
WHERE A.PAY_DE BETWEEN '20190101' AND '20191231'  
HAVING(ROUND(AVG(A.PAY_AMT), 2)) >= 4500000 ##### 이렇게 
GROUP BY A.EMP_NO
ORDER BY A.EMP_NO;
```


**NVL 함수는 값이 NULL인 경우 지정값을 출력하고, NULL이 아니면 원래 값을 그대로 출력**
```
SELECT 1, 2 FROM DUAL WHERE 1=2;
SELECT NVL(1, 0) FROM DUAL WHERE 1=2;
#1=2 결과는 공집합(실행결과 없음)이 나오고 에러는 안나옴  

SELECT NVL(MAX(1), 1) FROM DUAL WHERE 1=2;
#결과는 1

SELECT MAX(1) FROM DUAL WHERE 1=2;
SELECT MAX(NVL(1, 1)) FROM DUAL WHERE 1=2;
#결과는 NULL
```  
**count(*)은 NULL값까지 포함해서 계산하지만 count(컬럼)은 null값을 포함하지 않음**  
'''
SELECT COUNT(*)
from SELECT NULL AS NUM FROM DUAL #집계
'''
